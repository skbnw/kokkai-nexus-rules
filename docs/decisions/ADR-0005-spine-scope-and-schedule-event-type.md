# ADR-0005 — 背骨の収録範囲（scope）と、報道系日程の `event_type`

| 項目 | 内容 |
|---|---|
| 状態 | **承認**（2026-09-08 / Souichirou）。全項適用済 |
| 起票日 | 2026-09-08 |
| 影響する規約 | `COMMON_RULES.md` §5-8-b（event_type 登録簿）／§1-P7（後世への責任）／§1-P2（非削除） |
| 関連 | ADR-0003（`event_type` 拡張）／ADR-0004（案B）／設計書 §7-1 |

---

## 1. 文脈 — 起票のきっかけと、より深い問題

### 1-1. きっかけ（当初の想定）

ADR-0003 は却下案Aで「`other` で代用すると分類が死ぬ」と警告した。
Phase 4 で報道系の予定 3,163件を背骨へ投入したところ、**全件が `event_type='other'`** になり、
警告どおりの事態が現実になった。当初はこれを「政策日程に相当する種別が無い」問題と捉え、
種別追加の ADR を起票する予定だった。

### 1-2. 実データを見て判明した、より深い問題

`events.title` を実際に確認したところ、**種別の問題ではなく収録範囲の問題**だった。

投入したのは時事通信の**総合取材カレンダー**であり、政策日程ではない。

| category | 件数 | 実例 |
|---|---:|---|
| （policynews） | 828 | 公明党臨時党大会／GDP速報（内閣府）／貿易統計（財務省）／与野党の党首会談／短観（日銀） |
| 社会 | 616 | コロナ5類移行から3年／北海道地震から8年／スペースワン「カイロス」3号機打ち上げ／衆院選「1票の格差」訴訟判決 |
| 国際 | 568 | 10月の米貿易収支／ロシア下院選・統一地方選／**ベネチア国際映画祭**／日豪首脳会談 |
| スポ | 448 | **プロボクシング日本フェザー級王座決定戦／ゴルフISPSハンダ／大相撲秋場所番付発表／F1オーストリアGP決勝** |
| 経済 | 443 | 6月の月例経済報告／**株主総会―ホンダ**／G7エネルギー相・財務相・中央銀行総裁会合 |
| 政治 | 260 | 第221特別国会開会式／日独防衛相会談／春の褒章発表／国民健康保険の上限額引き上げ |

**F1のレース日程とベネチア国際映画祭が、日本政治インテリジェンスの背骨に入っている。**

### 1-3. 政治性の実測

件名に政治・行政・司法・統計の語（国会／内閣／閣議／大臣／省庁／党／選挙／法案／政令／審議会／
首脳／日銀／統計／GDP／訴訟／判決／最高裁 等）が含まれる割合:

| category | 件数 | 該当 | 割合 |
|---|---:|---:|---:|
| （policynews） | 828 | 687 | **83.0%** |
| 政治 | 260 | 210 | **80.8%** |
| 社会 | 616 | 414 | 67.2% |
| 経済 | 443 | 251 | 56.7% |
| 国際 | 568 | 254 | 44.7% |
| **スポ** | **448** | **3** | **0.7%** |

スポの3件はキーワードの誤ヒット（「大臣杯」等）であり、実質ゼロである。

### 1-4. 規約との関係

- `CLAUDE.md` プロダクトゴール: 主要軸は **政策 / 政局 / 選挙 / 報道**
- §1-P7（後世への責任）: 採否基準は「後世の検証に必要か」。
  **F1のレース結果は後世の政治検証に必要ない**
- §5-8-c（粒度の線引き）: `events` は「会議体・事象の1回」を表す。
  背骨は横断参照のための構造であり、参照先を持たない事象を入れる意味がない

---

## 2. 決定すべきこと

**Q1（範囲）**: 背骨 `events` に何を収録するか。
**Q2（種別）**: 収録するものに、どの `event_type` を与えるか。

Q1 が決まらないと Q2 は決められない。順序を誤ると、範囲外のデータに種別を付ける作業が無駄になる。

---

## 3. 決定

### 3-1. 収録範囲の原則（Q1）

> **背骨 `events` は、政策・政局・選挙・行政・司法に関わる事象のみを収録する。**
> 判断に迷う場合の基準は §1-P7「後世の検証に必要か」とする。

除外は**物理削除しない**。§1-P2 に従い `is_hidden = true` ＋ `hide_reason` で表現する。
`v_political_calendar` は `where not is_hidden` で除外済みのため、ビューからは自動的に消える。
範囲の判断が後日変われば `is_hidden = false` に戻せる。

**先行適用（2026-09-08）**: `category='スポ'` の448件を非表示にした。
政治性 0.7%（実質ゼロ）であり判断の余地が無いため。`hide_reason` に本 ADR を記録済み。

```sql
update public.events
   set is_hidden = true,
       hide_reason = 'ADR-0005: 収録範囲外（スポーツ日程）。背骨は政策・政局・選挙・行政・司法に限る'
 where created_by = 'sync:jiji' and category = 'スポ';
```

### 3-2. 残りのカテゴリの扱い — **案C を採用（2026-09-08 決定・適用済）**

`社会` / `国際` / `経済` は政治性が 44.7〜67.2% で混在しており、機械的に切れない。
以下から選ぶ必要がある。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A** | 全件残す（スポのみ除外） | 取材予定表としての実用性を保つ。判断コストゼロ | 背骨に映画祭・株主総会が残る |
| **B** | `政治` ＋ policynews のみ残し、他3カテゴリを非表示（1,627件を非表示） | 背骨が政治事象に純化する | 「1票の格差訴訟判決」「日豪首脳会談」等の重要事象を落とす |
| **C** | カテゴリではなく**件名ルール**で判定し、人間が確認して確定 | 精度が最も高い | ルール整備と目視確認の工数。§1-P5 により人間確定が必須 |
| **D** | 全件残し、`events.category` で運用上フィルタする | 実装コストゼロ | 「背骨に何が入るか」の基準が無いままになる。同じ問題が別ソースで再発する |

> **採用: C**。B は 1,627件のうち政治性のあるもの（社会414・国際254・経済251 ＝ 919件）を巻き込んで落とす。
> D は基準を先送りするだけで、官報・TV字幕など次のソースを入れるときに同じ判断を再び迫られる。

**司法の扱い（2026-09-08 決定）**: `court` 415件は個人の刑事事件を含めて**全件収録する**。
重大事件の公判日程は取材予定としての実用性があり、司法は収録範囲に含まれるため。

### 3-2a. ルール整備の実績

決定論的な正規表現ルールを **4回反復**して整備した（LLM を使わないため `is_ai_generated` は false）。
各反復で落選分を目視確認し、取りこぼしを拾い直した（§1-P5「確定は記名の人間」）。

| 反復 | 範囲外の総数 | うち `政治` | うち policynews | 拾い直した主なもの |
|---|---:|---:|---:|---|
| v1 | 838 | 53 | 183 | — |
| v2 | 641 | 29 | 96 | 補正予算案の審議入り／参院予算委 集中審議／マネーストック（日銀）／APEC閣僚会議 |
| v3 | 612 | 15 | 81 | 参院決算委／衆院代表質問／茂木外相のサウジ訪問／企業団体献金 |
| **v4** | **603** | **11** | **79** | 日米豪印外相会合／参院政治倫理審査会／日韓首脳の法隆寺視察 |

**ルールの評価順序に意味がある**（上から順に、より具体的な種別を先に判定する）。
順序を変えると結果が変わるため、編集時は必ず件数分布を再確認すること。

**既知の限界**: 3,163件中1件の誤分類を確認している。
「ノーベル平和賞を受賞した日本被団協の結成から70年」が「協議会」に反応して
`advisory_council` になった。ルールベース分類の限界として記録する。

### 3-2b. 適用結果（2026-09-08・本番 `polidata-db`）

| event_type | 件数 | | event_type | 件数 |
|---|---:|---|---|---:|
| `statistics_release` | 624 | | `press` | 99 |
| `court` | 415 | | `committee` | 89 |
| `cabinet_decision` | 353 | | `plenary` | 51 |
| `policy_schedule` | 312 | | `advisory_council` | 43 |
| `diplomacy` | 245 | | `party_meeting` | 33 |
| `election` | 189 | | **`other`** | **0** |

- 物理件数 3,504（**削除ゼロ**・§1-P2）／可視 2,453 ／非表示 1,051（スポーツ448 ＋ 範囲外603）
- `hide_reason` が空の非表示: **0**（§5-8-e の MUST NOT を遵守）
- 可視イベントで `event_links` を持たないもの: **0**（§1-P3 の逆引きを維持）

### 3-3. `event_type`（Q2）— 範囲確定後に適用

現行の登録簿では、報道系の予定に与えられる適切な値が `other` しかない。
実データの内訳（件名のキーワード一致・重複あり）:

| パターン | 件数 | 現行で表現できるか |
|---|---:|---|
| 統計・指標の公表（GDP速報・短観・貿易統計・月例経済報告） | 476 | ✗ |
| 判決・公判 | 350 | ✗ |
| 会議・本部・サミット・首脳会談 | 270 | △（`party_meeting` は党内会合のみ） |
| 国会（本会議・党首討論） | 200 | ○ `plenary` |
| 選挙（投開票・告示・公示） | 156 | ○ `election` / `gazette`（ADR-0003） |
| 記者会見 | 116 | ○ `press` |
| 審議会・分科会・部会・懇談会 | 113 | △（`committee` は国会委員会の意） |

**追加を提案する値**:

| 値 | ラベル | 定義 |
|---|---|---|
| `statistics_release` | 統計・指標の公表 | GDP・短観・貿易統計・月例経済報告など。政策判断の入力となる定期公表 |
| `advisory_council` | 審議会・分科会 | 行政の諮問機関。国会の `committee` とは別 |
| `court` | 判決・公判 | 司法。選挙訴訟・行政訴訟を含む |
| `diplomacy` | 首脳・閣僚級の外交日程 | 首脳会談・外相会談・国際会合 |
| `policy_schedule` | 政策関連の予定（形態未確定） | 上記いずれにも確定できないが政策・政局に関わるもの。`other` の受け皿を分離する |

`statistics_release` は政策インテリジェンスの中核である（「短観の翌週に金融政策決定会合」のような
時系列の連鎖が追える）。`court` は選挙訴訟を背骨に載せるために要る。

## 4. 却下した代替案

| 案 | 内容 | 却下理由 |
|---|---|---|
| **E** | スポーツも含めて全件を背骨に残し、種別 `sports` を足す | §1-P7 に反する。背骨は横断参照のための構造であり、参照先を持たない事象を入れる意味がない。プロダクトゴール（政策/政局/選挙/報道）からも外れる |
| **F** | 範囲外のレコードを物理削除する | §1-P2（非削除）違反。`is_hidden` ＋ `hide_reason` で表現する |
| **G** | `event_type` を増やさず `other` のまま運用する | ADR-0003 却下案Aと同じ。3,163件が `other` では集計・絞り込みが機能しない |
| **H** | 収集側（`polidata_schedule`）でスポーツを取得しない | 収集の網羅性を損なう。§1-P2 の精神（記録は残す）にも反する。**収集は全件・背骨への昇格時に選別**が正しい |

H は重要な線引きである。**収集層は絞らない。背骨へ上げるときに絞る。**

## 6. 検証方法

1. `select event_type, count(*) from events where not is_hidden group by 1` に `other` が偏らない
2. `v_political_calendar` にスポーツ日程が出ない
3. 非表示にした行が物理的に残っている（`select count(*) from events where is_hidden` > 0）
4. `hide_reason` がすべて埋まっている（理由なき非表示が無い）

---

## 7. 教訓（次のソース投入時に繰り返さないため）

本件は「収集したデータを、選別せずに背骨へ流し込んだ」ことで起きた。
官報・TV字幕・議事録など次のソースを入れるときも同じ判断が要る。

> **昇格の前に「このソースのどの部分が背骨に入るか」を決める。**
> 収集層（Bronze/名寄せ）は網羅的でよい。背骨は選別する。
> この線引きを `COMMON_RULES.md` §5-8-e として規約化することを提案する。
